# AGENTS.md — dsh-web-ask-aside

This file is the operating contract for agents working in this repository. It
supplements the user's global rules; where a rule here is more specific, it wins
for this repository. The project ledger is `PROJECT.md` — read it first.

## Read first

1. `PROJECT.md` — phase ledger, slices, acceptance commands, resume point.
2. `docs/requirements.md` — numbered, testable requirements and explicit non-goals.
3. `docs/adr/` — accepted decisions. Do not silently reverse one; write a new ADR.
4. `README.md` / `README.zh.md` — user-facing behavior and limits.
5. `docs/deploy.md` — release, smoke test, rollback.

Phase ids `P0`–`P5` and slice ids `S1`–`S5` are defined in `PROJECT.md`. Never
mark a phase or slice `done` unless its artifact exists and its acceptance
command actually passed.

`pnpm run check` must exit 0 before every commit. Run `pnpm run test:e2e` for any
change that touches selection, slots, the sidebar, fork behavior, the draft, or
styles. A skip printed by the e2e (no `dsh` or no browser) is **not** verification;
report it as unverified.

## Architecture invariants

- Build only on public DSH Client services and Slots. Do not import
  `@deepseek-ai/dsh-client-ui-primitives` or other undeclared/private packages.
  `dsh.client.inject` only orders activation.
- `src/client/dsh.ts` is the one adapter for DSH service shapes. When a Client API
  changes, update that file and its tests together; do not scatter casts through
  components.
- `src/client/selection.ts` is the one adapter for Chat DOM markers
  (`data-chat-turn`, `data-chat-flow`). No other module may query them.
- React, React DOM, `react/jsx-runtime`, and every `@deepseek-ai/*` module stay
  external. Never bundle them; never add a second React.
- No runtime dependencies without an ADR. A dev dependency for tests, lint, or
  build is fine; a runtime dependency is a product decision.
- The trigger registers in `shell.overlay`; the tab type registers with
  `ctx.sidebarRightTabs`, and its body registers in `sidebar.right.pane.tab`; the
  body declares its session-scoped child slot. Keep every registration inside
  `ctx.effect` and return the disposer.
- The page must have exactly one trigger. Do not add a second overlay entry for
  the same feature.
- Do not replace the app root, append a second application to `document.body`, or
  write DOM outside a React component (the stylesheet injection is the exception).
- UI text goes through `ctx.locale`; `en` and `zh` dictionaries must have the same
  key set. No hardcoded user-facing strings.
- Style with `--dsw-*` / `--dsw-alias-*` theme tokens. Literal colors are only for
  artwork such as `icon.svg`.
- `lib/` is generated by tsdown. Never edit it by hand; rebuild and commit the
  source change instead.

## Identity invariants

These are released identities; changing any of them is a breaking change. Write a
new ADR, update requirements/ledger, and plan migration before changing one.

| Item | Value |
| :--- | :--- |
| npm package | `dsh-web-ask-aside` |
| Client module id | `dsh-web-ask-aside` (must equal the package name) |
| Bundle row id | `web-ask-aside` |
| Resource protocol / tab kind | `askaside` |
| Locale namespace | `webAskAside` |
| Tab type id | `dsh-web-ask-aside/tab` |
| Trigger overlay id | `web-ask-aside.trigger` |

The resource address prefix is `dsh-resource://askaside/session/`. Saved sidebar
layouts reference the tab kind and address; do not rename them in passing.

## Behavior invariants

- The parent Session must never receive a prompt, turn, tool call, or context
  entry from this plugin.
- Fork only through `ctx.sessions.fork`. Do not synthesize Session events or write
  into another Session's log.
- Fork cut: the selected closed turn's durable end; if the selection is in an open
  or streaming turn, use the latest completed turn and quote the visible passage.
- Open the side conversation through `ctx.sidebarRight.openResource(..., {
  preferNewPane: true })`. Do not bypass the sidebar controller to place a tab.
- Seed the draft only through `conversation.input.requestDraftInitialization`.
  Do not write into another module's editor.
- Never send a message automatically. The user sends the question.
- The side Session is a normal Session with normal tools and permissions. Do not
  describe it as read-only; a read-only preset is a new decision and a new ADR.
- A failure needs a localized, actionable state. Do not leave a silent no-op.
- Keep the trigger anchored to a visible line of the selection; if the selection
  is off-screen or collapses, hide it.

## Testing

- Pure logic: add a case to `tests/unit/*.spec.ts`.
- Registration, fork arguments, address, error mapping: extend
  `tests/unit/apply.spec.ts` with the fake Client context.
- User-visible flow: extend `tests/e2e/ask-aside.e2e.mjs`. It must use a temporary
  `DSH_HOME`, a generated fixture Session, and a headless Chromium-family browser;
  it must never read real user Sessions or call a model.
- Every behavior change needs a test at the lowest tier that can prove it. A bug
  fix needs a regression case.
- Tests must not require network access or credentials. Do not commit real
  conversation logs, screenshots of real conversations, or `.dsh` data.
- Unit coverage thresholds apply with `pnpm run test:coverage`; do not chase
  coverage with assertions that do not prove behavior.
- The e2e cleans its own temporary home/browser profile on success. Use
  `E2E_KEEP=1` or `E2E_HOME` only for diagnosis, then clean up.

## DSH compatibility

- `engines.dsh` is the compatibility contract: currently
  `>=0.2.1-rc.2 <0.3.0-0`. Do not widen or narrow it without testing the target
  DSH and updating ADR-0006.
- Client APIs in 0.2.x are pre-1.0. Treat new service, slot, and DOM assumptions as
  compatibility surface, not as stable public API.
- When DSH changes, the fix belongs in `src/client/dsh.ts` and/or
  `src/client/selection.ts`, with tests. Do not spread `any`/casts through
  components to make a build pass.
- Do not edit a user's real profile or real `DSH_HOME` from this repository's
  scripts. The e2e uses its own temporary home; the project itself must not
  depend on the developer's profile.

## Workflow

- `PROJECT.md` is the ledger. Update the phase status, slice status, acceptance
  result, and decision log as work lands. Never keep state only in chat.
- One slice per commit; keep the repository green after each one. (The initial
  bootstrap commit may contain the scaffold and its first slices; after that, one
  slice per commit.)
- If the repository has a GitHub remote, branch before committing, open a PR, wait
  for CI, and merge through the PR. Do not push directly to `main`. Load the
  `github-issue-pr-workflow` skill before issue/PR actions.
- Without a remote, local commits on `main` are acceptable; never invent a remote,
  a CI result, or a published version.
- Commit messages: `<type>(<scope>): <summary>` (for example
  `fix(client): keep the trigger above the selection`). The body states what
  changed, the verification commands, and any accepted limitation.
- Do not commit `lib/`, `node_modules/`, `coverage/`, `.DS_Store`, editor state, or
  files under `/tmp`.
- Expensive-to-reverse decisions get an ADR: language/build, package identity,
  fork semantics, extension surface, distribution, compatibility. An ADR has
  Status, Context, Decision, Alternatives, and Consequences; it is immutable once
  accepted.

## Release

- The release gate is `docs/deploy.md` (P5), not a chat claim. Every box must be
  ticked before `P5 = done`.
- Before tagging: bump the version, update `CHANGELOG.md`, run `pnpm run check`,
  `pnpm run test:e2e`, `bash scripts/workflow-check.sh --strict .`, and inspect
  `npm pack --dry-run --ignore-scripts`.
- Publish with `npm publish --access public --provenance`. Do not assume npm auth;
  check `npm whoami` first.
- After publishing, install the exact version into a clean temporary profile and
  verify the row, the trigger, and the side pane.
- Rollback: `npm deprecate dsh-web-ask-aside@<version> "<reason>"`, publish a fixed
  version, and restore the profile bundle if needed. Never rewrite a published
  tag or reuse a version.
- Never publish from a dirty tree, a failing gate, or a browser e2e that did not
  actually run.

## Security and privacy

- The forked Session has the same tools and permissions as a normal Session. Do
  not claim the feature is a sandbox or read-only Q&A.
- Do not put credentials, real session logs, user paths from private sessions, or
  personal screenshots in the repository, tests, fixtures, or commit messages.
- Do not run destructive commands against `~/.dsh`, a user profile, or user
  Sessions. The e2e fixture lives under a temporary home and is disposable.
- Keep the client bundle free of private DSH modules; the public module table and
  public Slots are the supported boundary.

## Definition of done

A change is done when all of the following are true:

- `pnpm run check` exits 0.
- For UI behavior, `pnpm run test:e2e` exits 0 and prints `E2E PASS` (not a skip).
- The relevant unit/component tests cover the new behavior or regression.
- `docs/requirements.md`, `PROJECT.md`, and any affected ADR still match the code.
- No new console errors and exactly one selection trigger in the page.
- Package contents are unchanged or the change is intentional and recorded.
- Temporary files are reported to the user and not committed.

## Do not

- Do not rename the package, module id, row id, protocol, tab kind, or locale
  namespace without an ADR and a migration plan.
- Do not import private DSH packages or copy host components wholesale.
- Do not append Session events, write another Session's log, or patch the Chat
  renderer.
- Do not send a side-ask message automatically.
- Do not mark a phase/slice `done` on a skipped or unrun acceptance command.
- Do not commit generated build output, user data, or temporary files.
